# Where decode time goes: CPU and GPU profile (T5)

*2026-10-23*

**Did:** Three measurements: (1) decode speed for 16 to 47 MoE layers' experts on the CPU, fitted to a line;
(2) a microbenchmark of exactly one layer's CPU expert work (6 of 256 NVFP4 experts); (3) an Nsight Systems
timeline of 64 decode tokens. Also checked the RAM's configured speed and raw bandwidth.

**Expected:** The CPU streams experts at ~25–42 GB/s (Strata's range); GPU and CPU take turns, so the GPU idles a
lot.

**Got:**
- Decode time is a straight line: **6.98 ms + 0.245 ms per CPU expert layer.** With every expert on the GPU,
  llama.cpp would reach ~143 tok/s.
- CPU kernel alone: **207 µs per layer = 51 GB/s** on 14 P-core threads, better than expected. E-cores: 33 GB/s;
  all 30 threads: 23 GB/s. Inside llama.cpp each CPU layer costs ~245–280 µs, so ~40–75 µs goes to hand-off.
- **The GPU is busy only 48% of decode time**; the rest it waits for CPU layers. Its matrix-vector kernels run at
  ~268 GB/s (~60% of 448), activation quantization takes 12% of GPU time, and a token launches ~1,850 kernels.
- **The RAM runs below spec:** a DDR5-6000 CL30 kit at 4800 MT/s (XMP off), 70.5 GB/s measured read bandwidth.

**Takeaway:** The plan holds. With ~89% cache hits (T4) the CPU's ~1 ms of expert work per token can hide behind
the GPU, so an engine with llama.cpp-level GPU kernels should land near ~145–160 tok/s (1.6–1.75× the tuned
baseline), and ~200 tok/s with GPU kernels at ~80% of bandwidth (*estimates*). Enabling XMP is a free ~25% on
the CPU side for every setup.
