# EAGLE-3 draft head, local pilot: the pipeline works, the head is too weak yet (T9)

*2026-10-23*

**Did:** Built the whole pipeline for training an EAGLE-3 draft head for Flint on this PC, and ran it once at pilot
scale:

1. `tools/t9/make_prompts.py`: 2,300 coding and agent prompts (Magicoder, self-oss-instruct, OpenCodeInstruct,
   SWE-bench Verified rows 100-499; none from the routing set or the benchmarks).
2. `tools/t9/generate.py`: Flint answers them through our server with its recommended sampling (temperature 1,
   top-p 0.95, top-k 20), 4 parallel requests: 2.34M answer tokens in 3.1 h at a steady 213 tok/s.
3. `tools/t9/feature_dump.cpp`: replays every prompt + answer through our engine and stores, per token, the inputs
   of layers 2, 24, 46 (what llama.cpp's EAGLE-3 reads) and the final hidden state: 2.98M tokens, 49 GB, 35 min
   at ~1,440 tok/s. Check: the stored final state reproduces Flint's own next token 90% of the time on answers.
4. `tools/t9/train.py`: a 133M-parameter head that mirrors llama.cpp's `eagle3` graph, trained on Flint's
   next-token distributions with EAGLE-3's training-time test (7 unrolled steps), 32K draft vocabulary (99.93% of
   tokens). 3 epochs, 44 min.
5. `convert_hf_to_gguf.py --target-model-dir` (Flint's config and tokenizer) -> 271 MB GGUF;
   `SPEC=eagle ./run-flint.sh` loads it next to our engine.

**Expected:** 1.15-1.3x faster generation from the pilot head (first-token accuracy ~60-75%).

**Got:**

| | Result |
|---|---|
| Validation, first draft token correct | 42.2% (steps 2-7: 36, 34, 32, 31, 29, 28%) |
| Accepted per 3-token draft, predicted from validation | 0.62 |
| Accepted per 3-token draft, measured in llama.cpp (unseen prompts like the training mix) | 0.72 greedy, 0.68 sampled (23-24% of drafts) |
| Same on the long-file benchmark prompts (2K, 8K) | 0.25-0.28 (8-9% of drafts) |
| Generation speed | 86-107 tok/s on the training-style prompts, 71-78 on long files (vs 112-121 without a head) |

- The pipeline is right: llama.cpp accepts as many drafts as validation predicts, and the head's graph, input
  convention (token[P+1], g[P]), RoPE layout and feature layers were checked against llama.cpp's code. My earlier
  expectation compared the wrong numbers (first-token accuracy vs acceptance per drafted token).
- The head is weak because of data: 2.3M answer tokens, where EAGLE-3 heads are usually trained on tens to hundreds
  of millions. It is weakest on long contexts: no pilot sequence is longer than 3.3K tokens.
- A head that drafts 3 tokens and gets ~0.7 accepted costs more than it saves: speculation needs roughly 1.5+
  accepted tokens per step to pay off here.
- Tried: starting the head's output layer and final norm from Flint's: worse (29.9% vs 34.4% at step 400), dropped.

**Takeaway:** Scale up the data. Running now, unattended (`tools/t9/full_run.sh`): 20,010 new prompts (agent and
issue prompts from SWE-bench's train split), 8 parallel requests for 20 h, then features and 2 epochs of training.
This replaces the planned cloud run (T9.4). Long-context acceptance stays a known gap.
